# 业务规则

- 订单以（租户, 订单标识）唯一；重复受理必须被拒绝且不改变已存在单据。
- 未收金额 = 订单金额 − 已收金额；收款不得超过未收金额。
- 跨租户读取一律按“不存在”处理，不得泄漏对象是否存在。
- 金额以最小货币单位的整数表示，不使用浮点数。

## 退款

- 退款针对已受理订单的已收金额提出；受理需提供退款标识、订单标识、金额与原因。
- 退款金额必须为正整数且不超过订单金额，否则按参数不合法处理。
- 可退金额 = 已收金额 − 已生效退款合计（待处理退款同样占用可退额度）；退款金额超过可退金额即额度越界，拒绝受理。
- 指向不存在或跨租户订单的退款一律按“不存在”处理，不泄漏对象是否存在。
- 退款单状态：待处理（pending）、已生效（effective）、已冲正（reversed，终态）。受理成功即为 pending。
- 冲正：对 pending 或 effective 退款单冲正后进入 reversed，其占用的可退额度立即释放，可再次受理同额退款；对已冲正单重复冲正返回冲突且不改变状态。冲正必须原子，失败不留部分占用或部分释放。
- 在任意受理、冲正序列后，均满足：可退金额 = 已收金额 − (待处理 + 已生效)退款合计，且 占用额度 ≤ 已收金额 ≤ 订单金额。

## 结算

- 结算单是独立单据，以（租户, 结算单标识）唯一；受理需提供结算单标识、订单标识、结算金额、引用退款单标识集合与原因。金额以最小货币单位的正整数表示。
- 目标订单必须存在且属于同一租户；不存在或跨租户一律按“不存在”处理（404），不泄漏对象是否存在。重复受理同一结算标识返回冲突且不改变已存在单据。
- 受理为薄校验：只校验订单归属、结算标识唯一与退款集合（非空、不重复）；引用的退款单是否存在、状态、归属与金额合计均在推进时判定。受理成功结算单为待处理（pending），不改变退款状态，也不额外占用额度（额度在退款受理时即被待处理退款占用）。
- 结算单状态：待处理（pending）、已生效（effective，终态）。读取返回结算单标识、订单标识、结算金额、关联退款标识集合、状态、创建时间与更新时间，按租户隔离，跨租户读取按“不存在”处理。
- 推进：把结算单引用的待处理退款逐张置为已生效，使其真正占用可退额度，同时结算单进入已生效。推进必须原子——要么引用的全部待处理退款进入已生效且结算单进入已生效，要么全部保持原状、结算单保持待处理。
- 推进失败原因必须可区分：引用的退款单不存在或跨租户（按“不存在”处理）、引用退款属于其他订单、引用退款已冲正、引用退款已被其他结算单核销、结算金额与引用退款合计不符。
- 同一张退款单只能被一个结算单核销一次；结算单进入已生效后，其引用的退款不得再被其他结算单核销。待处理退款允许同时被多张待处理结算单引用；并发推进由写事务串行化，只允许一个生效，其余返回冲突且不改变已存在数据。已生效结算单不得重复推进，重复推进返回冲突且不改变状态。
- 任意受理、收款、退款受理/冲正、结算受理/推进序列后，仍满足：可退金额 = 已收金额 − (待处理 + 已生效)退款合计，且 占用额度 ≤ 已收金额 ≤ 订单金额。推进只在待处理与已生效之间迁移退款，不改变占用合计。

## 幂等重放

- 受理、冲正与结算受理/推进均以（租户, 操作, 目标标识, 请求指纹）去重，请求指纹由 `Idempotency-Key` 请求头提供。结算操作名为 `settle_accept`、`settle_advance`，目标标识为结算单标识。
- 同一请求指纹重复提交返回与首次相同的业务结果（含首次的错误），不产生第二次受理、第二次扣减、第二次释放或第二次状态翻转/额度占用。
- 不同请求指纹对同一目标标识并发提交时只允许一个生效，其余被拒绝且不改变已存在数据。
- 去重记录持久化落库，服务重启后同一请求仍识别为重放。
- 读取（GET）天然幂等，不纳入去重记录。
