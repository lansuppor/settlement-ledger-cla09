# 业务规则

- 订单以（租户, 订单标识）唯一；重复受理必须被拒绝且不改变已存在单据。
- 未收金额 = 订单金额 − 已收金额；收款不得超过未收金额。
- 跨租户读取一律按“不存在”处理，不得泄漏对象是否存在。
- 金额以最小货币单位的整数表示，不使用浮点数。

## 退款

- 退款针对已受理订单的已收金额提出；受理需提供退款标识、订单标识、金额与原因。
- 退款金额必须为正整数且不超过订单金额，否则按参数不合法处理。
- 可退金额 = 已收金额 − 已生效退款合计（待处理退款同样占用可退额度）；退款金额超过可退金额即额度越界，拒绝受理。
- 指向不存在或跨租户订单的退款一律按“不存在”处理，不泄漏对象是否存在。
- 退款单状态：待处理（pending）、已生效（effective）、已冲正（reversed，终态）。受理成功即为 pending。
- 冲正：对 pending 或 effective 退款单冲正后进入 reversed，其占用的可退额度立即释放，可再次受理同额退款；对已冲正单重复冲正返回冲突且不改变状态。冲正必须原子，失败不留部分占用或部分释放。
- 在任意受理、冲正序列后，均满足：可退金额 = 已收金额 − (待处理 + 已生效)退款合计，且 占用额度 ≤ 已收金额 ≤ 订单金额。

## 结算推进（结算单）

- 结算单是独立单据：受理需提供结算单标识、订单标识、结算金额、引用的退款单标识集合（非空、去重）与原因说明。
- 受理时目标订单必须存在且属于同一租户；不存在或跨租户一律按“不存在”处理（404），不泄漏对象是否存在。同一租户重复受理结算单标识返回冲突且不改变已存在单据。受理成功后结算单为待处理（pending）。
- 结算单按标识读取，返回结算单标识、订单标识、结算金额、引用退款单标识集合、状态、创建时间与更新时间；读取按租户隔离，跨租户读取返回 404。
- 推进把结算单引用的待处理退款逐张置为已生效（effective），使其真正占用可退额度；推进成功后结算单进入已生效（effective）。
- 推进必须原子：要么全部引用退款进入已生效且结算单进入已生效，要么全部保持原状、结算单保持待处理，并给出可区分的失败原因：
  - 引用的退款单不存在（含属于其他订单的同租户退款）→ 不存在（404）；
  - 引用退款已被其他结算单核销 → 冲突（409）；
  - 引用退款已冲正（reversed）→ 冲突（409）；
  - 结算金额与引用退款合计不符 → 冲突（409）；
  - 已生效结算单重复推进 → 冲突（409），不改变状态；
  - 已撤销结算单再推进 → 冲突（409），不改变状态。
- 同一退款单只能被一张结算单核销一次：结算单进入已生效后，其引用的退款不得再被其他结算单核销（推进以声明表唯一约束兜底，并发推进仅一个成功，其余 409）。
- 待处理结算单之间允许暂时引用同一张退款；只有推进成功才占用核销声明，推进失败不留任何声明。
- 在任意受理、收款、退款受理/冲正、结算受理/推进/撤销序列后，均满足：可退金额 = 已收金额 − (待处理 + 已生效)退款合计，且 占用额度 ≤ 已收金额 ≤ 订单金额。推进只在 pending 与 effective 之间翻转，不改变占用总额。

## 结算撤销

- 仅已生效（effective）结算单可以撤销；撤销成功后结算单进入已撤销（revoked，终态），不得再次撤销，也不得再次推进。
- 撤销必须原子：同一事务内解除该结算单持有的全部核销声明（settlement_claims），并把其核销过且当前仍为已生效的退款单逐张置回待处理（pending）；要么结算单与全部核销一并解除，要么全部保持原状。
- 撤销后退款重新视为待处理并继续占用可退额度，可再次被其他待处理结算单引用并在推进时核销；同一退款同一时刻仍至多被一张已生效结算单核销，核销唯一性约束继续成立。
- 撤销解除的是结算单与退款之间的核销关系，不改变退款单本身状态：推进后又被冲正（reversed）的退款在撤销时保持已冲正。退款冲正只作用于退款单，与撤销互不替代。
- 失败原因可区分且不改变已存在数据：
  - 结算单不存在或跨租户 → 不存在（404），不泄漏对象是否存在；
  - 已撤销结算单重复撤销 → 冲突（409）；
  - 待处理（pending）结算单撤销 → 冲突（409）。
- 撤销与推进并发作用于同一结算单或同一批退款时只允许一个操作生效，另一个被拒绝且不改变已存在数据（写事务串行 + 声明表唯一约束兜底）。
- 撤销只在 effective 与 revoked 之间翻转结算单、effective 与 pending 之间翻转退款，不改变占用总额，故可退金额守恒关系继续成立。

## 订单对账

- 对账批次以（租户, 批次标识）唯一；发起需提供批次标识、订单标识与核对说明。批次指向不存在或跨租户订单一律按“不存在”处理（404），不泄漏对象是否存在。
- 同一订单同时只允许一个进行中的对账批次（部分唯一索引兜底）；已有进行中批次时再次发起返回冲突（409）且不改变已存在批次；并发发起时仅一个进入进行中，其余返回 409。
- 发起即在同一事务内执行：按订单读取当前已收金额、待处理退款合计、已生效退款合计与已生效结算单合计，得出核对结论并留痕，批次由进行中（in_progress）进入已完成（completed，终态）。
- 核对口径：已收金额 = 待处理退款合计 + 已生效退款合计 + 已核销结余，其中已核销结余 = 已收金额 −（待处理 + 已生效）退款合计；占用额度 ≤ 已收金额 ≤ 订单金额时结论为相符（balanced），否则为不符（mismatched）。
- 对账只核对与留痕，不改变订单、退款、结算单的任何状态与金额；完成后订单继续发生的收支变化不追溯修改已完成结论，需要时以新批次标识重新发起。
- 执行期间订单被收款、退款受理或冲正、结算推进或撤销改动时，对账要么基于改动前的读数原子完成并留痕，要么整体失败并返回可区分的冲突原因（409），不留进行中批次或部分结论。
- 对账批次按标识读取，返回批次标识、订单标识、核对说明、核对时各项合计、已核销结余、核对结论、状态与创建、完成时间；读取按租户隔离，跨租户读取返回 404。
- 对账以（租户, 操作, 批次标识, 请求指纹）去重：重复提交返回与首次完全相同的业务结果（含首次错误），不产生第二次对账、第二次留痕；去重记录持久化落库，重启后仍识别为重放。
- 对账不改动任何单据状态与金额，故任意操作序列后可退金额 = 已收金额 −（待处理 + 已生效）退款合计的守恒关系继续成立。

## 异常工单

- 工单把异常处理诉求登记成可跟踪的独立单据：受理需提供工单标识、订单标识与问题说明（非空）。目标订单必须存在且属于同一租户；不存在或跨租户一律按"不存在"处理（404），不泄漏对象是否存在，且不留工单。同一租户工单标识重复受理返回冲突（409）且不改变已存在工单。受理成功工单为待处理（`pending`）。
- 工单按标识读取，返回工单标识、订单标识、问题说明、状态、创建时间与更新时间；读取按租户隔离，跨租户读取返回 404。
- 工单状态机：待处理（`pending`）→ 处理中（`processing`）→ 已解决（`resolved`）→ 已关闭（`closed`，终态）；`pending`/`processing` 也可直接解决或关闭。
  - 处理：把 `pending` 工单推进为 `processing`；对已处于 `processing` 的工单处理为幂等成功，不再次翻转、不改变更新时间；`resolved`/`closed` 工单处理返回冲突（409）且不改变状态。
  - 解决：把 `pending` 或 `processing` 工单置为 `resolved` 并记录解决说明（非空）；已关闭工单解决返回冲突；对已解决工单再次解决返回冲突。
  - 关闭：把 `pending`、`processing` 或 `resolved` 工单置为终态 `closed`；对已关闭工单重复关闭返回冲突且不改变状态。
- 所有状态翻转均在单事务内原子完成，失败不改变任何已存在数据；工单的登记与翻转只作用于工单本身，不改变订单、退款、结算单与对账批次的任何状态、金额与结论。
- 对账未结清冲突：对某订单下工单执行解决时，若该订单存在结论为不符（`mismatched`）且已完成（`completed`）的对账批次，则解决被拒绝返回冲突（409）且不改变工单状态。判定以该订单最新一条已完成批次的结论为准：最新为 `mismatched` 即阻塞；以新批次重新对账得到相符（`balanced`）结论后即可解决。已关闭工单不受此限制（已关闭工单本就不能解决，返回非法状态翻转冲突）。
- 工单不存在或跨租户的任何翻转返回不存在（404），不泄漏对象是否存在。
- 工单四类写操作以（租户, 操作, 工单标识, 请求指纹）去重：同一指纹重复提交返回与首次完全相同的业务结果（含首次错误），不产生第二次登记或第二次状态翻转；去重记录持久化落库，重启后仍识别为重放。不同指纹指向同一工单并发提交时只允许一个生效，其余被拒绝且不改变已存在数据。

## 订单批量导入

- 批量导入把一批订单受理做成可校验、可断点续跑的导入任务：提交时给出任务标识与 CSV 内容（表头须恰为 `tenant,order_id,amount_cents,currency`，与订单示例一致；逐行为租户、订单标识、金额、币种）。任务以（提交租户, 任务标识）唯一，提交租户经 `X-Tenant` 传入；行内租户逐行生效（可混合多租户行），仅用于该行订单的归属与判重。
- 任务受理后立即逐行校验与受理，每行独立判定：金额须为正整数、币种须受支持（CNY/USD/EUR/JPY）、订单标识在该租户下尚未存在；合格行受理为订单（状态 `accepted`、字段与逐单受理一致），不合格行不受理、只记录错误原因。另对行须恰为 4 列、租户与订单标识非空做行级校验。单行失败不影响其他行。
- 批内去重：同一批内完全相同的重复行只受理先到的一行，其余记为重复错误；不同内容但（租户, 订单标识）相同的行也只受理先到的一行，其余记为重复错误。批内重复判定优先于金额、币种等其他校验。
- 每行在独立事务内判定：订单受理（或失败记录）与任务计数同事务提交，行只在已决后才计入已处理；整批执行失败（如服务中断）不得留下半行结果，也不得把同一行受理两次。
- 任务可按标识读取，返回任务标识、状态、总行数、成功数、失败数、已处理行数、错误清单（逐条所在行号、该行原始内容与失败原因，行号按数据区从 1 起计）与创建、完成时间。执行完成后任务进入已完成（`completed`，终态）；执行中失败或中断的任务保持未完成（`pending`）。
- 断点续跑：未完成任务可继续同一任务续跑，续跑只处理尚未处理的行，不重复受理已成功行，也不重复记录已判失败行。任意导入与续跑序列后，每行要么被受理一次、要么被判失败一次，成功数 + 失败数 = 已处理数，全部完成时已处理数 = 总行数，最终各计数与错误清单与一次性成功导入一致。
- 重放：重复提交同一导入任务标识且内容相同，返回与首次相同的业务结果（含首次错误结果），不产生第二次导入或第二次受理；去重以内容 SHA-256 指纹持久化在任务行上，服务重启后同一请求仍识别为重放。
- 冲突：同一任务标识不同内容并发或先后提交时只允许一个生效，其余返回 409 且不改变已存在任务与订单数据（写事务串行 + 任务主键唯一兜底）。
- 导入受理的订单与逐单受理的订单在读取、收款、退款、结算与对账各条链路上行为一致；跨租户读取导入的订单仍按不存在处理。
- 错误可区分：参数不合法 400（缺租户头、CSV 为空、表头不符、只有表头无数据等）；任务不存在或跨租户 404；同一任务标识以不同内容重复受理 409；内部错误 500（任务保持未完成、可续跑）。

## 出入库单

- 出入库单是对已受理订单发生的入库/出库记录，以（租户, 出入库单标识）唯一。受理需提供出入库单标识、订单标识、方向（`in` 入库 / `out` 出库）与数量（正整数）。受理成功后方向与数量保持原值，不再变更。
- 受理时目标订单必须存在且属于同一租户；不存在或跨租户一律按"不存在"处理（404），不泄漏对象是否存在，且不留单据。同一租户出入库单标识重复受理返回冲突（409）且不改变已存在单据（不以后到请求覆盖方向或数量）。
- 出入库单状态：已受理（`accepted`）→ 已撤销（`reversed`，终态）。受理成功即为 `accepted`；按标识读取返回出入库单标识、订单标识、方向、数量、状态与创建时间；读取按租户隔离，跨租户读取返回 404。
- 撤销（冲正）：对已受理单据撤销后进入终态 `reversed`，返回最新单据；`reversed` 单据不计入数量汇总。单据不存在或跨租户按"不存在"处理（404）且不改变数据；对已撤销单据重复撤销返回冲突（409）且不改变状态。撤销必须原子，失败不留部分状态翻转；同一单据至多冲正一次。
- 数量守恒：每租户每订单净出入数量 = 已受理入库单数量和 − 已受理出库单数量和（冲正单据计 0）；在任意受理、撤销、重放、并发与重启序列后均成立。
- 条件检索支持按订单标识、方向、数量区间（含端点）、创建时间区间（含端点）、状态（`status` 精确过滤）任意组合过滤，条件之间为逻辑与；`include_reversed=true` 返回全部状态，`status` 与 `include_reversed` 同时给出按参数不合法处理（400），都不传默认只返回 `accepted`。按创建时间升序、相同创建时间按出入库单标识升序排序；该顺序只依赖单据自身字段，稳定且不受插入先后与重复查询影响。
- 游标式稳定分页：游标指向上一页末条在（创建时间, 标识）排序中的位置，下一页严格从该位置之后续取；页内不重复、不漏项，任意分页大小与任意取页顺序下各页并集恰等于完整过滤结果集（含冲正单据的结果集同样成立）。结果数超过当页上限才返回续页游标，否则（含空结果）不返回游标。检索按租户隔离，空结果返回空列表。
- 出入库单的受理、读取、检索与撤销只作用于自身，不改变订单、退款、结算单、对账批次、工单与批量导入任务的状态、金额与结论；订单可退金额 = 已收 −（待处理 + 已生效）退款合计的守恒关系继续成立。
- 错误可区分：参数不合法 400/422（缺租户头、缺幂等键、方向非 in/out、数量非正整数、数量区间反向、`status` 非法、`include_reversed` 非布尔、`status` 与 `include_reversed` 同时给出、分页参数越界、游标非法）；对象不存在（含跨租户）404；重复受理或重复撤销 409；内部错误 500。

## 幂等重放

- 退款受理、退款冲正、结算受理、结算推进、结算撤销、订单对账、工单登记/处理/解决/关闭、出入库单受理与撤销均以（租户, 操作, 目标标识, 请求指纹）去重，请求指纹由 `Idempotency-Key` 请求头提供。
- 订单批量导入不使用 `Idempotency-Key`：以（提交租户, 任务标识）唯一、以提交内容的 SHA-256 指纹区分重放与冲突，同标识同内容为重放，同标识不同内容为 409。
- 同一请求指纹重复提交返回与首次相同的业务结果（含首次的错误），不产生第二次受理、第二次扣减、第二次释放、第二次状态翻转或第二次撤销。
- 不同请求指纹对同一目标标识并发提交时只允许一个生效，其余被拒绝且不改变已存在数据。
- 去重记录持久化落库，服务重启后同一请求仍识别为重放。
- 读取（GET）天然幂等，不纳入去重记录。
